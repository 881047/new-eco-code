# 编程与工程（本项目踩过的坑换来的规则）

## 一、SQLite（本项目唯一的真相源，11 GB）

- **只读打开**：`sqlite3.connect("file:<abs>?mode=ro", uri=True)`；写库前先 `backup_db.py`。
- **校验**：`PRAGMA quick_check` 扫描整库但便宜（10.33 GB 实测 **21 秒**）；
  `PRAGMA integrity_check` 更彻底但慢（同库 **339 秒**）⇒ 日常用 quick_check，年度体检用完整版。
- **在线备份**：`src.backup(dst)`（不是复制文件）——WAL 模式下复制文件会拿到不一致快照。
- 长驻进程里用 `db.conn_ctx()` 上下文管理器；直接 `get_conn()` 忘了 `close()` = 永久持锁。

## 二、Windows / 命令行

- **`.cmd` 批次文件必须 CRLF 行尾 + 纯 ASCII**：LF 行尾会让 cmd.exe 解析错位
  （实测报出 `'EALPY' is not recognized`；根因是行尾，不是编码）。`.gitattributes` 里钉 `eol=crlf`。
- **计划任务**：`schtasks /create` 不需要管理员；PowerShell `Register-ScheduledTask` 在根目录会被拒。
  默认 `<DisallowStartIfOnBatteries>true</DisallowStartIfOnBatteries>` ⇒ 笔记本用电池时不跑，需显式改 false。
  用 `InteractiveToken` 注册 ⇒ **只在用户登录时触发**。
- **无控制台环境**：`print()` 可能不可用（要在 `log()` 里加 try/except）；`.venv\Scripts\python.exe`
  是转发 stub，重定向不可靠 ⇒ 计划任务里用 `pyvenv.cfg` 的 `home` 解析真实解释器。

## 三、Python / 依赖

- 解释器用 `D:\Python313\python.exe`；`PYTHONPATH` 指向 `.venv\Lib\site-packages`。
  ⚠️ **2026-09-15 起 venv 不再是 stub**：3.13 迁移时套件被**重装进 venv 自己的
  `Lib\site-packages`（82 个 dist-info）**，numpy/pandas/lightgbm/fastapi 都从 venv 加载
  ⇒ `.venv\Scripts\python.exe` 现在是**自给自足**的解释器，文档里那条 canonical 命令
  在新机器上也能原样跑通（这正是 2026-09-14 外部审查要求的"命令可复现"）。
- LightGBM：`deterministic=True` + 固定 `seed` 才能复现；`bagging_fraction`/`feature_fraction`
  只有配 `bagging_freq` 与 seed 才稳定；**轮数固定时不要开 early stopping**（本项目 2026-09-04
  实测：早停平均只长 27 棵树、近期退化成单树桩）。
- pandas 3.x / numpy 2.x：`to_sql` 会警告需要 SQLAlchemy 连接（本项目直连 DBAPI，忽略该警告）。

## 四、测试纪律（本项目最贵的一课）

- **测试不许有对外副作用**：曾发生"pytest 真发出运维邮件""测试写生产日志"。
  做法：① 把副作用文件路径 `patch` 到测试目录；② 用 `setUpModule` 做**模块级子进程禁令**；
  ③ 验收看外部事实（例：跑完全量测试后 `notify_log` 的 max(id) 不许变）。
- **隔离必须是"多层 + 单一实现"**（2026-09-14，07 号 #53 之后定稿）。三层缺一不可，
  每层的哨兵都设在**边界**而不是内部函数：
  | 层 | 哨兵位置 | 为什么不是更里层 |
  |---|---|---|
  | 日志 | 环境变量 `NEWECO_LOG_DIR`（子进程继承） | patch 模块属性不会传给子进程 |
  | 邮件 | `smtplib.SMTP_SSL`（**唯一网络出口**） | 替 `_send_with_retry` 会漏掉 `scheduler._ops_alert_once` 的**重发分支**（它直连 `send_ops_alert`）；替 `send_ops_alert` 又会让"断言接管逻辑真实"的测试假红 |
  | 数据库 | `db.DB_PATH` → 临时库（`init_db()` + 只读 attach 复制参照表） | 只堵发信不堵落库 ⇒ `notify_log` 仍被测试写（证据台账污染） |
  **实现只有一份**：`tests/_isolation.py`。`tests/conftest.py` 与 `scripts/ci_run_tests.py`
  都调它，CI 入口在 `discover()` **之前** `setup()` + `assert_active()`；不生效就 exit 2，**拒绝开跑**
  （"宁可当场红，也不要静默污染台账"）。守卫：`tests/test_test_isolation.py`（5 条，含
  "两入口必须共用同一实现"的结构断言）。
  **验收口径（外部事实，不看自述）**：全量测试前后 `logs/app.log` 字节数**不变**、
  生产库 `notify_log` 行数**不变**、跑完的 `git status` 不含 `data/weekly/` 残渣。
- **"canonical 命令"必须真能跑**（2026-09-14，外部审查 §9.4）：文档里的
  `.venv\Scripts\python.exe -X utf8 -m pytest tests/ -q` 曾经**在收集阶段就 ERROR**
  （starlette 1.6 的 `TestClient` 要 `httpx2`，`requirements-lock.txt` 里没有），而审计脚本
  用 `D:\python` + PYTHONPATH 注入 venv site-packages 的**未声明组合**跑得出 1211 —— 于是
  "基线"依赖一个谁都没写下来的拐杖。现在 lock 里补了 `httpx2`（+`httpcore2`/`truststore`）
  与 `pyarrow`，两条路径都自给自足。**规则**：改依赖/测试入口后，用**文档里那条命令**跑一次；
  跑不通就改文档或改环境，不许让"基线只在某个未公开的解释器组合下成立"。
- **Windows Smart App Control 会按"文件声誉"逐路径拦未签名 DLL**（本机事实，2026-09-14 实测
  + 2026-09-15 复查）：`.venv` 里的 `pyarrow\arrow.dll`（与 `D:\python` 侧**哈希相同**、
  无 Authenticode 签名）曾被判"未达签名要求"拒绝加载（`CodeIntegrity` 事件 3033/3077），
  pandas 只报"pyarrow 未安装" ⇒ **极易误判成依赖缺失**。
  ⇒ 判据不能是 `import pyarrow`，而是**真实 parquet 往返**（`tests/test_market_cache.py`
  顶部的探测函数），不可用时 4 条显式 `skipUnless`（跳过数进 CI 额度 `SKIP_BUDGET=6`），
  并在理由里写明机器与策略。
  **2026-09-15 复查：该 DLL 已被放行**（同一路径、同一哈希，声誉缓存生效）⇒ 这 4 条现在真跑，
  全量 **1228 passed / 0 skipped**。**结论**：这是**机器级、随时间变化的**限制 ——
  测试写法（探测 + 显式跳过 + 写明理由）保持不变即可；**别去改系统的安全设置**，
  也别因为"今天能跑"就把探测逻辑删掉。
- **第二例（2026-09-25，W2 仓）**：`D:\ECO-W2\.venv` 里 pandas 的
  `_libs/tslibs/vectorized.cp313-win_amd64.pyd` 被同一策略拦下（CodeIntegrity 3033/3077，
  原因同为 "did not meet the Enterprise signing level requirements"；
  `VerifiedAndReputablePolicyState = 1`）。**危害比第一例大得多**：不是"某个功能不可用"，
  而是**整仓不可用** —— `pytest` **40 个 collection error**（全为
  `partially initialized module 'pandas'`）、`w2.panel` 导入失败、`run_paper` 起不来。
  ⚠️ **它是"新出现"的**：前一晚 20:31 W2 还 479 passed。
  **判据（怎么区分"是 SAC 拦的"而不是"依赖缺失/写坏了"）**：① 错误文案含
  **"应用程序控制策略已阻止此文件"**（SAC 专属，依赖缺失只会说 ModuleNotFoundError）；
  ② `Get-WinEvent -LogName Microsoft-Windows-CodeIntegrity/Operational` 里有 3033/3077
  且文件路径指向该 `.pyd`；③ **对照**：把**另一个环境里同版本**的同一个 `.pyd`
  复制到临时目录、用同一个 python 加载 ⇒ 若报的是 `PyInit_*` / 缺兄弟符号（**Python 层**）
  而不是 Code Integrity，就说明**该哈希已被放行、且声誉不跟路径走**。
  **处置（已实测有效）**：把 pandas **对齐到已知可用的版本**（W2 从 3.0.6 → **3.0.5**，
  与老盘一致）⇒ `pip install "pandas==3.0.5"`（只替换 pandas，numpy 不动），
  随后 W2 全量 **479 passed** 恢复。**仍然不改系统安全设置**（与第一例同一条纪律）。
  ⚠️ **防复发**：真正的办法是 `requirements-lock.txt`（老盘有、W2 没有）—— 只写
  `pandas>=2.2` 的话，全新建环境仍会解析到 3.0.6+ 再撞一次。2026-09-25 用户"暂不加"，
  故只在 `D:\ECO-W2\requirements.txt` 留注释与补救命令。
- **守卫测试要"先红后绿"**：先证明它能抓到那个 bug（在旧代码上失败），再在修复后通过。
- **统计实现必须带"合成数据自检"（2026-09-13，F56 PBO 当场抓错）**：写任何选择偏差/显著性指标
  （DSR、PBO/CSCV、HAC t、IC_IR…）时，先跑两个合成对照：①**纯噪声**臂集 → 指标应落在理论值
  （PBO≈0.5）；②给某臂加**恒定真优势** → 指标应给"无过拟合"（PBO≈0）。只跑噪声一侧不够 ——
  F56 第一版把 CSCV 的 OOS 名次方向写反（Bailey 定义里 r 是 **1=最差**），噪声侧照样 0.501 正常，
  真优势侧却给 **0.999**，**结论会从"未见明显过拟合"整个翻成"大概率是噪声"**。自检红了才发现。
- **弱断言**（只验"不抛异常"）等于没测 —— 本项目审查里专门点了四条。
- **活配置也要测**：`load_config()` 对不合法配置只打 ERROR 不抛（怕一个手改错字让整条链起不来）
  ⇒ 必须有测试断言"活 `config.yaml` 过 `validate_config`"（`TestLiveConfigPassesValidator`，07 号 #20）。
- **提交前核对 diff 与提交信息**：`git diff --stat` 里没有的文件，不许写进提交信息
  （该项目真实发生过：信息说修了 config，diff 里只有一份 md，07 号 #20）。
- **"测试有对外副作用"已四次复发**（#1 写生产日志 / #2 真发运维邮件 / #21 改写 config.yaml /
  **#32 又写 app.log + `data/weekly/_test_*.bak` 残渣**）⇒
  凡"真的走到端点或真实文件"的用例，必须在 `tearDown` 里**按外部事实验收**（文件字节 / DB 行数 /
  日志行数），而不是相信"我只是断言了状态码"。审计 `--tests` 已内置 config.yaml 字节守卫。
  ④ **多入口写入的目标（尤其日志目录）要用环境变量改道**，不要只 patch 模块属性：子进程会继承环境
  变量，patch 不会（`tests/test_logger_utf8.py` 就是起子进程跑的）。`app/config.py` 的
  `LOG_DIR` 现在认 `NEWECO_LOG_DIR`，`tests/conftest.py` 在收集前设置它、会话结束清 `_test_*` 残渣；
  验收看外部事实：全量测试前后 `logs/app.log` 的**字节数与行数完全相同**（2026-09-13 实测 2,228,742
  字节 / 24,070 行不变；改前同一批测试会写进去上千行）。
- **写回的序列化必须能 round-trip**（07 号 #21）：ruamel 把 float `0.00001` 写成 `1e-05`，
  而 YAML 1.1 不把 `1e-05` 当 float ⇒ "读-改-写"一次就把数字变成字符串。凡是**人改 + 程序写**的
  配置文件，都要有"写回再读，类型与值逐键相同"的测试。
- **诊断产物不许阻断主产品，但必须留痕**（2026-09-13，`scores.ic_or_none`）：逐期 IC 是诊断，
  算不出来（例：最小合成面板没有 `m["open"]`）时打分链**照常完成**，但要把
  `ic_skipped=<异常类型:消息>` 写进存档 meta —— "没有这项"与"忘了算"必须分得开。
  反例就是本项目反复踩的坑：静默跳过 ⇒ 半年后没人知道当初到底算没算。
- **实验脚本的构型常量必须与生产同源**（2026-09-13，07 号 #23）：`experiments/05_label/F*.py`
  一度各自写死 `hyst=0.2`，而生产 `pick_shape(1e6)` 是 `hold_bonus=0.0` ⇒ 路演数字描述的不是
  在跑的构型。现在有 **`SHAPE_LEDGER.json` 台账 + `tests/test_experiment_shape_ledger.py`** 守卫：
  新脚本必须申报构型、脚本里的常量必须与台账一致、台账的 `_production` 必须等于**实时**的
  `pick_shape(1e6)`、偏离生产的条目必须写明差多少。**新写实验时，构型请从 `pick_shape()` 取，
  不要写字面量。**
- **重算缓存的三条铁律**（2026-09-13，行情面板缓存 326s → 3s）：
  ① 缓存键用**内容指纹**（源表 `MAX(日期)` 等），不用文件 mtime —— 本项目账本/模拟盘写的是**同一个库**，
  mtime 一变就作废等于没有缓存；
  ② **只缓存大对象、且只在生产库写**：小窗口每次重算更省（还会按容量策略挤掉大缓存），测试/临时库
  写缓存会污染真条目（`_is_prod_db()` 闸 + `tests/test_market_cache.py` 10 条守卫）；
  ③ 缓存读回与原始查询**逐元素字节相同**（已实测），但**内存布局（C 序 vs F 序）会让 `nansum`
  这类聚合出现 1e-8 级差异** ⇒ 比较派生统计量时别把它误判成"数据变了"；要比就比字节（`tobytes()` 哈希）。
- **"实验读数 → 产品常量"必须带构型标签 + 守卫**（2026-09-13，07 号 #25/#26 两次同类缺陷）：
  从实验里抄进 `app/` 的任何数字（阈值、基线、文案里的配置值）都要写清"**在哪个构型、哪个窗口**测的"，
  并由测试钉住：① 能被实时配置覆盖的（如权益权重）**必须读配置**，不许写字面量；
  ② 纯基线常量（如回测换手 0.137）在被改时要有测试变红；③ 用户可见文案里**不许出现历史配置值**
  （`tests/test_no_stale_live_constants.py` 会静态扫描非注释行）。
- **无控制台上下文里不许裸起控制台子进程**（2026-09-13，07 号 #27 "闪窗"事故）：
  计划任务（Interactive only 跑 .cmd）与服务进程（`DETACHED_PROCESS` 拉起）都**没有控制台**，
  此时启动 cmd/git/python.exe 会让 Windows **新建一个控制台窗口**（用完即关 = 桌面闪一下）。
  规则：① 计划任务入口走**隐藏启动器**（`wscript //B` + `Run(..., 0, ...)`，启动器必须 ASCII+CRLF）；
  ② 生产代码里每个 `subprocess.run/Popen` 都要显式声明 `creationflags`（`CREATE_NO_WINDOW`，
  需要独立进程时用 `DETACHED_PROCESS`），由 `tests/test_no_flashing_subprocess.py` 静态扫描守住。
  ③ **"闪窗"的源可能不止一个**（#27 是 10 分钟计划任务、#29 是登录自启，同一句反馈两个源）：
   凡是"交互会话里跑批处理"的入口都要过隐藏启动器；**隐藏模式下禁止 `pause`**（看不见又等按键 =
   卡死），失败信息改写成日志。**别猜**：用 `scripts/diag_window_flash.py`（`SetWinEventHook` 抓
   `EVENT_OBJECT_SHOW`，报 `visible=Y/N` 与父进程链）取证，**先做阳性对照**再下结论；本机默认终端是
   Windows Terminal ⇒ 控制台闪现表现为 `WindowsTerminal.exe class=CASCADIA_HOSTING_WINDOW_CLASS`
   （不是老式 `ConsoleWindowClass`），只按旧类名过滤会漏报。
- **批处理（.bat/.cmd）：注释与控制流一律 ASCII**（2026-09-13，07 号 #30 实测 A/B）：
  cmd.exe 按**字节**推进批处理文件指针，含多字节字符的中文 `rem` 行会把偏移带歪、**吞掉下一行**
  （同一文件里：中文 rem → 下一行不执行；只把 rem 换成 ASCII → 同一行立刻正常写入）。被吞的可能是
  `goto`/`for`/`exit` 这类控制流，而**跑起来不报错**，`chcp 65001` 不免疫。规则：① `rem` 与
  `if/for/goto` 行写英文/ASCII；② 用户可见的顶层 `echo 中文` 可保留（`logs/launch.log` 多年实测正常）；
  ③ 守卫 `tests/test_service_watchdog.py::test_start_bat_keeps_comments_ascii`；④ 改完批处理要**数日志行数**
  验证，不能只看"窗口没出现 / 脚本没报错"。
- **测试要查"行为/契约"，不能只查"存在性"**（2026-09-13，07 号 #28 端点错位事故）：
  `assertIn("/api/weekly", spec["paths"])` 在**端点被换成带 body 的 helper** 时依然通过 ⇒
  线上 422 却测不出来。改成读 FastAPI 的 OpenAPI 断言**契约**（无参 GET 不许有 `requestBody`/必填参数），
  并做红线检查（把 helper 插回装饰器位置 ⇒ 断言变红）。同理：看板类字段要断言**取值来源**
  （实时 vs 快照），不能只断言"存在"。
- **给月频训练写集成测试的配方**（2026-09-13，`tests/test_trainer_run.py`，trainer 31%→65%）：
  ① 用**文档化的实验入口**而不是改生产行为 —— `factors_override=`（绕过 `factor` 表）、
  `archive_dir=`（把按月归档写到临时目录，不碰 `data/models/`）、`score_table="xxx_test"`（护栏要求必须给 archive_dir）；
  ② 迷你 LightGBM：patch `trainer.PARAMS`（num_leaves=4 / min_data_in_leaf=10 / n_jobs=1）+
  `num_boost_round=5, early_stopping_rounds=0, ensemble_seeds=[7]`；
  ③ **合成数据规模由代码里的硬门槛决定**：`len(X_tr) < 5000 ⇒ 跳过该月`，而默认 `holdout_recent=6`
  会再切掉 6 个月 ⇒ 至少要 ~200 股 × 36 月（≈6000 行）才训得出月份；
  ④ 临时库直接 `executescript(db.SCHEMA)`，实验表用 `CREATE TABLE x AS SELECT * FROM 生产表 WHERE 0` 复制结构（列不漂移）；
  ⑤ 值得断言的四条：该训的月份真的落库（分数行数 = 期数 × 票池）、**增量幂等**（第二次 trained=0）、
  **同种子全量重训逐位相同**、以及"非生产表未给 archive_dir ⇒ 拒绝"的护栏。
- **手工重启服务别忘清冷却**（2026-09-13 实拍）：看门狗有 5 分钟冷却，若刚拉起过就又杀掉再跑它，
  它会拒绝拉起、服务留在线下。正确顺序见 03 号运行手册（杀进程 → 删 `logs/service_watchdog.state` → 跑 watchdog → 探活）。

## 五、工程卫生（工具驱动的清单）
