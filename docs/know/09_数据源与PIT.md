### `report_rc` 补库的可用边界（2026-09-14 06:5x 实读，**新增**）

- **实读证据**：① 检查点 `data/.report_rc_backfill.json` 的 `done` 与 `empty` 是**同一批 54 个月**
  （`2020-08`~`2025-01`），`next_offset` 为空；② 表 `report_rc` 行数 **0**；③ 日志
  `logs/report_rc_backfill.log` 在这 54 个月逐个打印 `[warn] … 空页 ⇒ 记入 empty 并标完成`，
  到 `2025-02` 开始变成 `[err] … 频率超限(10次/天)`；④ 2026-09-14 06:2x 人工复调用 `2026-07`
  被拒（`1次/分钟`→`10次/天`）⇒ **当天额度已用完**。
- **推断（未核实）**：该 token 的 `report_rc` 可用区间大约**从 2025-02 起**（更早月份返回空页而不是报错）。
  设计期探针（2026-09-13）确实从 `2026-07` 拿到过 5000+644 行 ⇒ 近期数据是有的。
- **对使用的含义**：① 第二源**最多覆盖 ~20 个月**（2025-02 起），**不要**拿它跟主力源（东财，2020-08 起）
  做同窗对比；② 想重拉那 54 个空页月份，必须**手工**把它们从 `done`/`empty` 里删掉（脚本自己的口径
  就是这么写的），否则永远不会再试；③ 额度只有 **10 次/天** ⇒ 这件事按"天"推进，别当小时级任务排期。

### 限速与权限（会咬人的两条）

- **限速是账号级的**：`TushareClient` 的限速门为**类级**（2026-09-12 P2-20 修）。原实例级时，
  同进程 updater/regime 各 new 一个 client、各自以为"还没发过请求"，实际频率 = 实例数 × 187/分，一起撞 200/分 的墙。
- **错误分类不能只看关键词**：`"每分钟最多"/"频率"` = 限流（退避重试）；`"积分"/"权限"/"抱歉"` = 永久失败（不再重试）。
  2026-09-05 的坑：权限文案里带"抱歉"，被误判成限流 ⇒ 重试约 81 秒后炸断管线，AkShare 兜底永不触发。
- 接口可用性探测结果落盘 `data/.probe_cache.json`，**TTL 7 天**，跨任务复用，避免每天重复试探权限。

### ⚠️ 接口坑（会误导任何一次"再探一遍"）

**`index_basic` 的 `name` 参数是精确匹配，不是模糊匹配。** 实测：`name="800"` 返回 **0 行**，
而不带参数返回 8000 行里名字含 `800` 的有 **114 条**；`name="全收益"` 也返回 0 行，
而目录里含"全收益"的其实有 **1234 条** ⇒ **凭 `name=中证800全收益` 查不到 ≠ 该指数不存在**。
正确姿势：`index_basic(market="CSI")` 拉目录后**本地**筛 `name` 含关键字（本目录一次返回 8000 行，
疑似单页上限 ⇒ 按 `market` 分片查，别指望一次拉全）。`last_status` 可区分：
`empty`=查询成功但无数据、`perm`=积分不足 —— 探空时先确认是哪个。

## 二、每日链（`DataUpdater.run_daily`，18:00 档）

```
init_trade_cal → (触表 fund_basic) → init_stock_basic → sync_stock_market(daily / adj_factor / daily_basic)
→ init_index → [full: fund_daily / fund_adj / fina_indicator / namechange / repo]
→ sync_lhb → sync_new_sources
```

- 日线**按日增量 + 自动补齐**（缺哪天补哪天），三重自愈：接口权限不足 ⇒ 终止本轮（下次续跑）；
  连续 10 天确认无数据 ⇒ 终止；`daily` 单日 < 1000 行 ⇒ 记警告（疑似残缺批，次日重拉自愈）。
- 起点 `START_DATE = 20130101`；交易日历覆盖到 **2027 年底**。
- **`full=True` 有历史自愈**：财务期数 < 40 期时自动全量补齐（2026-09-05 修）——
  否则新装机只拉最近 8 期，36 个月训练窗的历史财务因子永久缺失且无提示。
- `stk_limit`（交易所公布涨跌停价）是**真值对照表**、不在每日链里更新；10 号文件的涨跌幅规则用它逐格实测过。

## 三、PIT（时点）引擎：六层过滤

`app/pit/engine.py::tradable_mask`，与生产训练的 `trainer.tradable_mask`（内嵌闭包）是**同一套口径**：

| # | 层 | 规则 |
|---|---|---|
| 1 | 已上市 | `first_trade <= d − 60 交易日`（`LISTED_MIN_DAYS=60`） |
| 2 | 未停牌 | `vol(d) > 0` |
| 3 | 非 ST/退 | **d 当天的时点名称**不含 `ST`/`退`（`NameLookup.name_at` ← `namechange`） |
| 4 | 板块 | 科创（`board.is_star()`，含 689 CDR）按 `star_enabled`；北交按 `allow_bse` |
| 5 | 市值 | `total_mv >= 截面 size_pctl 分位` |
| 6 | 流动性 | 近 20 日均成交额 `>= min_amt20` |

- **首现日锚定上市日**：`first_trade = max(数据首现, list_date)` —— 北交所在精选层时期就有新三板交易数据，
  只按"数据首现"会把前视引进来。
- **板块单一真源** `app/portfolio/board.py`：689 CDR 与 688 同规则（07 号第 9 条）。
- **可交易性近似**：停牌用 `vol == 0` 判（`suspend_d` 表不存在）；一字板买卖顺延在成交层实现（见 10 号）。
- **行业口径**：默认仍是**当前快照**（`stock_basic.industry`，与生产 `factor` 表同口径）；
  `industry_at(pit=True)` 只留钩子、**不假装有数据**。申万一级 PIT 映射
  `holder_factors.sw_industry_map_pit` 只用于 `pit` 那个 die 的中性化（F22）。
- **可审计**：`pit.audit(dt)` 返回每层剔了多少只 —— 过滤必须可解释。

## 四、使用注意

- 一次性脚本/测试用模块级 `tradable_mask(m, dates, dt)`（无缓存、每次自建）；重复问询用 `PITEngine()` 实例（构造一次）。
- `neutralize` 有 **float32/精度漂移**：换个面板列集或行数，同一截面会末位不同（12 号）。
  **想逐位复现就逐日调用**，别为省事"整块算"。
- 稀疏事件面板**不要**直接喂 `fe.neutralize`：2%/98% winsorize 会把非零占比 <2% 的行整行归零
  ⇒ z-score 全 NaN ⇒ IC 静默消失（F35 踩过，专用实现在 `experiments/05_label/F35_event3_weekly_ic.py::neutralize_sparse`）。
