# pin 台账（基线 pin：唯一判据"改动有没有动基线"）

> 本文档 2026-09-13 建立，起因：独立审查 §4.4 发现**四处脚本把当时的 pin 写成"现行 pin"**，
> 而 pin 的值恰好是"改动是否改了基线"的**唯一判据** ⇒ 带着过期 pin 复核会得出反向结论。
> 根因是"pin 值散落在各处注释里、没有单一台账"。这份就是那个单一台账。

### ⚠️ 两把基准尺并存（2026-09-20 起，读任何"超额"前先看这段）

| 键 | 值 | 服务谁 |
|---|---|---|

  做 `_deep_merge(DEFAULT_CONFIG, user)` ⇒ **删掉 config.yaml 那行 = 仍是全收益**。
  要退回价格指数尺必须**显式**写 `benchmark_nav_code: 000906.SH`。
- 旧 pin 行 `20260912_limitquant` **仍在库里不删**（按本台账"保留不自清"纪律）。
  拿新 pin 比旧 pin 时有两处**与换尺无关**的已知差：`avg_turnover 0.8912→0.9018`

## 三、口径陷阱（本次一并查清）

- `exp_illiq_stress.py` 的 `START=20200831` 与 `exp_fb_window.py` 的 `START=20200930`

## 四、改 pin 的规矩（三步同步，缺一不可）

1. `config.yaml` 的 `backtest_run` 注释：写下新值 + 变更原因 + 哪次实验决定的；
2. **本台账**：把旧值移进"历史 pin"表，新值填进"现役 pin"；
3. 受影响脚本/文档的注释：**要么更新、要么显式标注"历史值"** —— 不允许留"现行 pin"这种会过期的措辞。

另外：换 pin 必须走"**A/B → 预注册 → 重钉 → 提交带 Δ**"，禁 `REGEN_GOLDEN=1`。

## 五、"触及判据适用条件"类改动的换 pin 处理（2026-09-24 首例）

> 起因：`01` 号 §一.5b 定了"仅改报数/呈现口径 ≠ 换 pin；**凡触及预注册已冻结的阈值/窗口/参数
> ⇒ 一律换 pin**；边界写不下的场合**从严**"。2026-09-24 出现了第一例"边界写不下"的改动，
> 本节记录判法，供下次照此办理。

### 首例：健康档「换手」判据加样本量守卫（07 号 #63）

| 项 | 内容 |
|---|---|
| 改动 | `app/weekly/health.py`：新增 `TURNOVER_MIN_DAYS = 4`；`evaluate(..., n_turnover=0)` **默认即"样本不足"**；`n < 4` 时换手**不得单独升级到 `degrading`**（仍可 warning）；`current()` 返回真实 `turnover_n` |
| 为什么算"触及" | `BACKTEST_TURNOVER`（0.137）与 2×/3× 倍数**一字未动**，但**"什么时候用这条阈值"变了** ⇒ 属 5b 的"边界写不下" ⇒ **从严按换 pin 处理** |
| 预注册 | `plans/health-turnover-guard-prereg-20260924.md` |
| **重钉实测** | `scripts/pin_baseline.py --tag turnguard`（2026-09-24 22:2x，**399 s**）⇒ run `20260924_turnguard` / `20260924_turnguard_full` |
| **Δ** | **逐位为 0**：85 期 满仓 **17.82% / −28.38%**（夏普 0.617）、系统 **14.97% / −22.80%**（日频 −32.77%）、IC 0.0962 / ICIR 0.862、实持 5.00 / 闲置 28.06% / 换手 **89.54%**；full 115 期 满仓 **8.34% / −51.26%**、系统 **7.13% / −42.10%**（日频 −42.64%）—— 与现役 `20260922_trbench`（08 号 §一）**逐键一致** |
| **处置** | **不重钉**：`config.yaml: backtest_run` **保持 `20260922_trbench` 不动**；`pin_baseline.py` 打印的 `backtest_run: 20260924_turnguard` 块**只是它的"供你粘贴"输出，本脚本不改 config**（脚本自身纪律），本次**有意不粘** |
| 留痕 | run 行 `20260924_turnguard` / `_full` **保留不自清**（沿用本台账纪律），供复核 |

**判法的可复用部分（下次遇到"改适用条件"照此走）**：

1. 先判**是否触及**：改的是"读数怎么呈现"（不触及）还是"阈值/窗口/参数/**它们的适用条件**"（触及）；
2. 触及 ⇒ **按换 pin 走**，哪怕预期 Δ=0 —— 因为"预期"不是证据；
3. **重钉必须实跑**，把 Δ **写出来**（本次 Δ 逐位为 0 ⇒ 不重钉）；
4. Δ=0 时**不动 `config.yaml` 的 pin 值**，但**必须在本台账登记这一行**（否则下次有人看到 `pin_baseline.py` 的输出会以为 pin 换过）。

**与 07 号 #46 的区别（同段代码、不同判法，必须写清）**：#46 修的是**空序列 ⇒ NaN**
（纯空值防护，不改判据适用条件）⇒ 当时**未走**换 pin；本条改的是**判据的适用条件**
（"n 不足时不许升级"）⇒ **走**。若将来有人问"为什么同一个函数两次判法不同"，答案就是这一句。

### ⚠️ 该 Δ **不是**「执行层 alpha」的证据（本轮最重要的判读）

翻开关的**唯一正当理由是消灭回测/实盘撮合分叉** —— 实盘 `app/paper/engine.py:148`
一直是「次日开盘价 + 滑点」成交，回测此前却用收盘价：同一决策日两套撮合，
`engine.py:54-60` 注释早已登记为冲突、A/B 未决。**不是因为 +7pp 才翻。**

`scripts/oneoff/diag_exec_pin_delta_20260928.py` 按 **trade_date 严格配对**两 run 的
NAV 序列后（⚠️ 首版误用 `ORDER BY nav` 按净值排序 ⇒ 月度 Δ 全是噪声、结论作废，
已修正并留痕），Δ 的三项稳健性判据**全部不达标**：

| 判据（预注册冻结） | 门槛 | prod | full |
|---|---|---|---|
| 配对差 \|t\| | ≥ 2 | **1.84** ❌ | **1.74** ❌ |
| Δ 符号一致率 | ≥ 2/3 | 46/38 = **54.8%** ❌ | 59/55 = **51.8%** ❌ |
| 最大 3 月占 Δ 比 | ≤ 60% | **67.3%** ❌ | **64.8%** ❌ |

- 月度 Δ **中位数仅 +0.018pp（prod）/ +0.009pp（full）**，均值却 +0.493pp ⇒ 高度右偏，
  靠少数月撑起。符号翻转率 67%（接近随机，不是持续同向）。
- 最大贡献月 **20201030：old −1.06% → new +12.60%**（单月 +13.66pp）；最差月都是
  「old 大涨 / new 涨得少」—— Δ 呈**以 old 高收益月为代价**的分布。
- **合成 golden 宇宙上同口径只有 +0.41pp（系统）且系统回撤恶化 0.35pp、胜率 −3.45pp**
  （合成数据无真实隔夜-日内结构）⇒ 反证真实数据上的 +7pp 主要来自少数事件月。
- **遗留乐观偏差**：开盘成交仍沿用 `slip=0.001`（10bp）。微盘股开盘流动性差，
  实盘真实滑点可能显著高于此 ⇒ 本读数偏乐观，待实盘 `price_fn` 实测对账。

⇒ **对外引用产能时不得把 +7pp 记作策略提升**；它只是「回测终于用了实盘那套撮合」后
的读数变化。旧 pin 值仍可回滚（`backtest_run` 改回 + 两开关翻回 False）。
