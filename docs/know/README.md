## 三条使用规则

1. **先查台账再动手**：`05_实验台账.md` 里已否掉的方向，不要重跑（除非有新证据）。
2. **口径必须带窗口**：本项目历史上最贵的坑就是"同一个数字换了口径"（见 `07_事故台账.md`）。
3. **改完回来更新本库**：任何改变口径/参数/流程的改动，必须同步这里，否则知识库本身会变成误导。
4. **理论层要先过转换协议**：理论层的结论不构成上线依据；任何"应该有效"的推断必须走
   `20` 号第五节的七步（可检验假设 → 查证伪 → 预注册 → 最小实验 → 两轴 → 独立复核 → 回写台账）。

## 仓库镜像（2026-09-13 补）

本库 canonical 在 **`D:\know`**（用户指定）。但它建在仓库外 ⇒ git 里看不见、也没有历史 ——
**这正是用户当天问"知识库怎么不见了"的根因**。现在仓库里有随提交走的镜像
**`D:\NEW ECO\docs\know\`**：

```powershell
# 改完本库后同步（单向：D:\know → docs\know）
D:\Python313\python.exe -X utf8 scripts\sync_know.py
# 只检查是否一致（CI/审计用）
D:\Python313\python.exe -X utf8 scripts\sync_know.py --check
```

同一个脚本还把 **Codex skill `new-eco-know`**（`D:\codex-home\skills\new-eco-know`，
讲"哪件事读哪一份"、报数与动手铁律）镜像到 **`docs/codex-skill/new-eco-know/`** ——
它同样建在仓库外、同样会丢。skill 在 Codex 里用 `$new-eco-know` 触发（自动发现，无需手动加载）。

工程审计（`scripts/audit_engineering.py`）第 9 项 + `tests/test_know_mirror.py` 会守住这两份镜像：
**改了源不同步 ⇒ 测试与审计都会红**（测试还验 skill 的 frontmatter 可加载、路由指向真实存在的文件）。
clone 到别的机器时镜像仍可读（源不存在时测试跳过）。
