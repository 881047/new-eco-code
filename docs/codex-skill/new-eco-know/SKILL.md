## 报数铁律

任何超额/收益数字必须同时给：**窗口 / 基准 / 成本口径 / 样本外标记**，并注明来源实验编号与 pin。
只报好看的半边 = 误导。当前数字一律**现读** `02`、`08`，不要凭记忆或会话记忆报。

## 动手铁律（这几条踩过坑，代价真实）

- 判据**先冻结再跑数**；跑完改判据必须如实登记，不许静默放宽。
- 组合层判决看**两轴**：超额 **和** 最大回撤。IC 只作参考（已三次实证与头部收益反相关）。
- 改回测/成交/标签口径 = **换 pin**：A/B → 预注册 → 重钉 → 提交带 Δ。禁 `REGEN_GOLDEN=1`。
- `05_实验台账.md` 里已否掉的方向**不要重跑**，除非有新证据并重新预注册。
- `scripts/oneoff/` 是证据：不得删除、不许批量搬家；其中 5 个写生产表的脚本有 `ONEOFF_CONFIRM` 护栏。
- 改了 `app/**` 必须重启服务（uvicorn 无 `--reload`），见 `03`。

## 改完知识库必须同步镜像

```powershell
D:\Python313\python.exe -X utf8 scripts\sync_know.py            # 单向 D:\know → docs\know

```

漏同步 ⇒ `tests/test_know_mirror.py` 与 `scripts/audit_engineering.py` 第 9 项都会红。
新增/改名知识库文件后，同时更新 `D:\know\README.md` 索引。

## 写知识库的规则

只写经核实的事实；推断必须标注「推断」；数值必须带窗口/口径/来源。
结论分三类写清：已核实的事实 / 合理推断 / 未核实。改了口径或流程，必须回来改本库，否则知识库本身会变成误导源。
