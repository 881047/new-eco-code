# LLM 参与的因子发现·第一轮执行计划（2026-09-16 冻结，09-17 开工）

> 用户拍板方向：现有因子众所周知，利用已接入的 LLM 提升模型能力。
> 本文件是**开工前冻结的计划**——明天按此执行，判据与预算不再改。

## 定位与铁律

- LLM 只做**提案者**（读数据字典与现役因子 → 提表达式+经济含义），判决永远归
  Alpha Factory 的预注册门禁（`declare()` 冻结分母 → 死区评估 → IC/KGD → OOS）；
  LLM 输出**绝不直接进生产**，组合层两轴判决另行预注册。
- 诚实预期：台账历史 10+ 轮模型改造大部分被杀；本轮的首要目标是**跑通
  LLM→Proposer→工厂的完整链路**，产出候选进 `alpha_bank`（CANDIDATE），
  而不是承诺出因子。

## 执行步骤（明日开工顺序）

1. **新数据族盘点**（~20 分钟）：`broker_recommend`（券商金股）、`research_report_em`
   （研报评级/目标价/EPS）、`top10_holder`（十大流通股东）、`dividend_ts`（分红送转）
   四张表的行数/覆盖窗口/PIT 键（ann_date）→ 产出一份**数据字典**（LLM 的阅读材料）。
2. **写 `scripts/llm_factor_propose.py`**（~40 分钟）：DeepSeek 输入 =
   31 现役因子清单 + 新族数据字典 + 工厂 DSL 算子表（Alpha158 同族）；
   输出 = JSON 提案数组（表达式 / 依赖字段 / 经济含义 / 建议持有期 / 与现役因子的
   差异化理由）。**预算冻结：首轮 3 批 × 10 条 = 30 条**（Bonferroni 分母=30）。
3. **进工厂**（~30 分钟）：提案 JSON → `LLMProposer` → `Factory.declare()` →
   `run()`（死区评估）→ 门禁 → 结果登记 `alpha_bank`（CANDIDATE/POOLED/杀）。
   DUPLICATE 杀掉的如实记录（预期大部分与已知因子撞车——这正是门禁的价值）。
4. **收尾**：结果摘要（过闸/被杀/存疑三栏）登记台账 + 汇报；过闸者的组合层
   两轴判决**另开预注册**，不在本轮。

## 可选追加（开工时再确认）

- **候选池清理**：用已跑完的 LLM 因子审读结果（40 条的红旗/verdict）把低价值
  候选标记退役 → 缩小未来轮次的 Bonferroni 分母。零模型风险。
- **LLM 文本信号**（研报标题/龙虎榜原因逐事件打分）：成本最高、最不确定，
  建议等第一轮表达式提案的结果出来后再评估是否值得。

## 明确不做

- 任何绕过工厂直接把 LLM 输出接进打分/交易的路径；
- 更改超参数/标签/融合（台账已证伪并关闭的方向，除非有新独立证据重新预注册）。
