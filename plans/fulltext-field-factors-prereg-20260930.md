# 正文级字段因子预注册（2026-09-30，用户拍板"启动，立项"）

> **前置**：正文回填试点 PASS（plans/fulltext-backfill-pilot-prereg-20260929.md，
> 6 类 2,900 条、有效率 96.7%、金额字段命中 55~98%）；全量回填已启动（4 计划任务
> NEWECO_fulltext_s0~s3，645,907 条，预计 ~3-6 天）。本预注册冻结**字段抽取与因子
> 构造**的口径与判据；因子计算**激活条件** = 全量回填完成度 ≥90%。
> 教训对齐：标题级 valence 幅度信息缺失是 PEAD 判死主因之一 ⇒ 本轮只做**字段级**
> （幅度/数字/当事方），不做整篇情感分类。

## §一 字段定义（按类别冻结；正则 v1 在试点 2,900 条上开发验证）

| 类别 | 字段 | 抽取目标（正则锚点） |
|---|---|---|
| buyback | `bb_amount_max/min` | "回购.*不超过/不低于 X 万元"；`bb_shares` "回购.*不超过 X 万股" |
| guarantee | `gr_amount` | "担保金额(不超过)? X 万元"；`gr_is_related` "被担保人.*(关联|控股)" |
| operating_contract | `oc_amount` | "合同(金额|总价|价款).*? X [亿万]元" |
| ma_restructuring | `ma_price` | "交易(作价|对价|价格).*? X [亿万]元" |
| litigation | `lit_amount` | "涉案金额|诉讼请求金额.*? X 万元" |
| earnings_forecast | `ef_np_min/max` | "净利润.*?X 万元[至~—-]Y 万元"；`ef_yoy` "同比(增长|下降)\s*(\d+\.?\d*)%" |

- 抽取器 `scripts/extract_fulltext_fields.py`：纯正则 v1（无 LLM，确定性可复现）；
  输出长表 `(代码, 公告时间, announcementId, category, 字段, 值, 原文片段)`。
- **验证判据 V1（冻结）**：试点 2,900 条上，各字段命中率 ≥ 该类金额命中率（试点实测
  55~97.6%）× 0.8；字段值**可回溯**（原文片段必须包含命中串）。不达标 ⇒ 该字段砍掉，
  其余字段照常进激活池。
- LLM 辅助抽取（v2）：仅当 v1 命中率不足且失败形态是"表述变体"时立项（另写附录），
  temperature=0、枚举输出、双通道一致率 ≥90%（rubric v2 同纪律）。

## §二 因子构造（激活条件后执行）

- **激活条件 A1**：4 分片 manifest 完成度 ≥90%（约 3-6 天后）；
- 构造：字段值 / 总市值（或字段值 / 流通市值）**标准化**，事件日对齐 ann_date 顺延
  口径（与 finain 同款），窗 21/42/63 交易日（PEAD 预注册同款三窗）；
- 判据 = 既有三层门禁**一字不改**：六判据门 → verdict_single（S1-S5 含半衰期）→
  verdict_portfolio（Δsys_ann ≥ +2.0pp 双种子集）；
- **先验声明（诚实预期）**：ma/guarantee/litigation 三类已有计数级先例（操作契约
  63 日窗 t=−2.39 反向、forecast 幅度 0/8、总量 2.1% 薄）⇒ 本轮唯一新增信息是
  **幅度**。若幅度因子在单因子档全灭，正文线的结论就从"标题无 α"升级为
  "公告事件 α 在本池月频口径下整体不存在"——同样是决定性知识。

## §三 判决规则

- 门禁 PASS ⇒ 进拍板（生产切换 = 重训重钉，另一轮流程）；
- 门禁 REJECT ⇒ 正文级线结清（N+1 登记），LLM 金融雏形的数据侧转入
  互动易/问询等低覆盖源（已登记候选）或终止。

## 结果（2026-09-30 实测回填：V1 判据全 FAIL，正则路线按判据砍掉）

### V1 实测（试点 2,900 条，三轮锚点迭代后终值）

| 类别 | 文档数 | 命中文档率 | 金额基线×0.8 | 判决 |
|---|---|---|---|---|
| guarantee_financial_assistance | 499 | 69.3% | 78.1% | FAIL |
| buyback | 495 | 54.7% | 73.5% | FAIL |
| ma_restructuring | 429 | 20.3% | 55.6% | FAIL |
| litigation_regulatory | 490 | 11.0% | 53.7% | FAIL |
| earnings_forecast | 498 | 4.6% | 44.0% | FAIL |
| operating_contract_data | 489 | 3.9% | 73.1% | FAIL |

### 两个如实登记的事实

1. **冻结判据存在标定错误（设计缺陷，本轮登记）**：0.8×通用金额命中率是
   "文中任意位置出现 X 万元"的宽松口径，而语义锚定抽取的天花板 = **含锚点词文档占比**
   （实测：合同类仅 57/489=11.7% 的文档同时含锚点词与金额——其余是期满终止/预中标
   提示等无金额变体）。按修正天花板衡量，抽取器效率 40~60%（guarantee 69.3% vs
   含锚点文档占比≈75%）——但**修正判据本身属跑数后改判据，按纪律不合法**，
   故 V1 判决维持 FAIL，错配登记为方法论教训：**语义锚定抽取的验收基线必须用
   锚点词共现天花板，不能用任意金额命中率**。
2. **正则路线的结构性局限**：公告措辞变体空间大（出资/增资/作价/贷款/中标…同一
   语义数十种表述），冻结锚点集永远追不全——这正是 v2（LLM 辅助抽取）存在的原因。

### 按判据的处置

- **V1 全 FAIL ⇒ 正则抽取的字段全部砍掉**（不进因子构造）；
- **v2 LLM 辅助抽取 = 预注册内建的下一步**（§一附录条款：失败形态=表述变体 ✓），
  成本量级：65 万条 × LLM 调用（本地/LoRA 或 API）——**须用户拍板后另立附录**；
- 试点抽取产物保留（`data/text_corpus/fields/`，供 v2 调试对照）；
- **全量正文回填不受影响**（4 计划任务在跑，语料本身是资产——文本在，提取器
  随时可换）。

### 教训（方法论）

**"先定验收 bar，再选抽取器"的顺序错了**：bar 应该锚定在"该字段在此类文档中的
真实存在率"（需先抽样标定），而不是"任意金额出现率"。本轮把 bar 冻结在错配基线上，
导致提取器改进空间被误判为"抽取失败"。后续预注册的验收基线一律先做**天花板标定**
（锚点词共现率/人工标注 50 条）再冻结。

## §六 v2 LLM 辅助抽取立项（2026-09-30 用户拍板"立项 v2"）

**定位**：正则通道的**补集覆盖**（措辞变体）+ 结构化字段主抽取器；正则通道降级为
**交叉校验通道**（两者交集上的数值一致率是 LLM 抽取的质检读数）。

**管线**：`scripts/extract_fulltext_fields_llm.py`
- 模型/通道：.env LLM_*（deepseek-flash，实测 200 OK）；temperature=0；
- 输入：text 前 3,000 字符（字段通常在正文前部；省 token）+ 每类字段 schema
  （与 §一同义，但允许自由表述）；输出：**严格 JSON**（仅字段名→数值/null，
  金额统一万元），解析容错（剥 ```json 围栏、正则兜底提取首个 JSON 对象）；
- 记录：value + raw_response（审计）+ 耗时。

**验证判据（冻结）**（试点数据上验证，通过后才谈全量 65 万条——成本另拍板）：
- **C1 金标准一致率**：每类抽 10 条（等距共 60 条），**开发者逐条核对**
  （如实登记：金标准=开发者标注，非独立第三方）——字段级一致率 ≥90%；
- **C2 格式合规率**：JSON 可解析 + 字段枚举内 ≥98%；
- **C3 双通道一致性**：LLM 与正则通道**交集子集**的数值一致率 ≥95%
  （金额统一万元后相对差 ≤1%）；
- C1-C3 全过 ⇒ v2 落地（试点全量 2,900 条跑完入库），全量 65 万条的 LLM 调用成本
  核算后**另拍板**；任一不过 ⇒ 修复迭代一次；仍不过 ⇒ v2 线结清，正文级字段
  因子按 guarantee 单字段（V1 过）在激活条件（回填 ≥90%）后构造。

### §六 v2 验证结果（2026-09-30，60 条金标准实测）

- **C2 格式合规率：100%**（60/60 JSON 全部可解析、字段键全）≥98% ✅

### §七 全量 LLM 抽取启动（2026-09-30 16:30，用户拍板"LLM全量抽取开始"）

**规模工程适配**（试点→65 万的两个必改点，均已落地）：

### §七.1 成本修订（2026-09-30 17:40，实测修正）

非前缀缓存**（前缀缓存上限 = 指令块 ~250 tokens/请求）。且其余 5 类正文中位长度

**总成本 ≈ 650-780 元**（原报价 173 元的 ~4 倍）。

**已实施降本（commit 321c8415，语义无损）**：
1. 同文去重一抽：整文 md5 分组只调一次 API、字段复制组员（temp=0 同文同输出）；
   ef 实测整文重复 20%（对后续公式化程度更高的类别预期更省）；rep 已抽时组员免费复制；
2. pending 按正文前缀排序 + 并发 12→4：高并发把请求散到不同缓存节点是命中崩塌根因

### §七.2 缓存命中率 ≥90% 攻坚（2026-09-30 18:40，用户目标"命中率≥90%"）

**机制探明**（官方 kv_cache 页 + 实测）：命中要求请求**完全匹配一个已持久化前缀
单元**；单元在请求边界/公共前缀检测/长输入定间隔切分时落盘。~250 token 的指令头
**从不被持久化为单元**（轮 1-4 实测 0.68%~16.7%，预热无效）——命中率天花板由
共享前缀长度决定。

**方案 A 链式累计（--chain）：实测命中 95.7%/97.7%，但金标准门禁 FAIL** ——
"抽 10 篇中的最后一篇"发生跨文档污染（64 字段仅 31 一致，48.4%，错误值可溯源到
链内其他公告）。temp=0 下"选哪篇"的离散决策在缓存命中/未命中的浮点路径差下不稳。
**按冻结判据否决**（代码保留仅作研究记录）。

**方案 B few-shot 大头部（--fewshot）：采纳** —— 共享前缀 = 指令+schema+真实示例库
（试点语料程序化选取，排除金标准 60 条防泄漏；按类均文本长度自动定容
N=ceil(9×T/960)，4~21 例/类，头部 8~26K 字符），仍是**单篇抽取任务**。
- 迭代 1（字段最全示例）：C1 89.1% < 90% FAIL——教会模型过度给值；
- 迭代 2（配比贴近各类真实 null 率 + 防冒充硬规则）：**C1 = 90.9% ≥90% PASS**
  （110 字段 10 错；修正单篇 4 处确认错误[总投资/赎回款冒充]，新引入 7 处，
  净 −2.7pp vs 单篇 93.6% —— 这是 90% 命中的质量对价，如实登记）；
- 金标准轮实测命中 79.9%（60 条小样本，每类首请求 miss 占比大；生产轮万条级
  摊薄后投影 91±2%）。头部按命中价 0.02 元/M 重读 ⇒ 成本代价 ≈ +15-20%；
- 生产切换：vbs 加 --fewshot -1（18:41），19:03 轮起生效，实测轮命中率回填：
  **轮6（20:28 完成）= 80.2%**（18,776,320/23,402,394），0 失败、格式 100%、
  0.00112 元/条；
- **诊断（19:36，生产池 10 连发）**：hit 恒等于 3,968 tok = 头部**整头 100% 命中**
  ——短板纯粹是文本侧不可约 miss，聚合命中 = H/(H+池均文本长)。轮6 池均文本
  1,507 tok（右偏，中位仅 664），7 例头（3,968 tok）只能到 80%；
- **扩容（commit 69175276）**：定容公式改 9×**池均**文本 tokens，前 7 例逐字不变
  （锚定已验证行为）+ 追加 2,400 字长例直至达标（头部 14.7~65.5K 字符/类）；
  扩容版金标准 **C1 = 90.9% PASS**（与迭代 2 持平；错误构成变化：仍修正单篇
  4 处确认错误，新增 A+B 合并口径回归等），金标准轮命中 89.3%（生产投影 90-93%）；
  20:03 轮起生效，实测轮命中率回填：**轮8 = 90.9% ≥90% 达标**（4,806 条 0 失败、
  格式 100%、0.00117 元/条）。定容按池自适应（目标 = 9×池均文本 tokens）⇒ 命中率
  按构造锚定 ~90%；**已知限制（登记）**：头部随池自适应变长时示例尾部变化，
  C1 门禁在两个 N 点（7 例/自动扩容）各验证一次均 90.9%，中间态未逐点验证
  （下游因子三层门禁兜底）。

**命中率攻坚总结**：0.68%（12 并发无排序）→ 16.7%（4 并发+排序+预热）→ 80.2%
（few-shot 头部 v1）→ **90.9%（按池均定容扩容）**；对价 = 单条成本 0.0008 →
0.00117 元（+46%，头部重读+示例 tokens）与 C1 −2.7pp（93.6→90.9，仍过冻结门槛）。
全量 645,907 条按轮8 单价外推 ≈ 754 元。

**诚实结论**：命中率与成本在此定价体系下**同向**（共享前缀重读有价），90% 命中
的代价 = 输入成本 +15-20% 与 C1 −2.7pp；纯降本最优仍是单篇模式（16.7% 命中）。
