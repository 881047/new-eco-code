# D 案落地：因子分组监控 / 归因层（2026-09-22）

> 性质：重组方案 D 的设计与落地计划（零口径变更）。顺序依据：用户拍板"先做 C，C 被证伪再做 D"。
> C 已判 effect_indistinguishable（05 号台账 2026-09-22 C 案条目）⇒ 本计划生效。
> 前置证据：`experiments/factor_corr_36m.csv`（36 个月末截面 Spearman 均值）、C 案 6 块映射。

## 一、原则

**输入层一字不动**：31 因子 → neutralize → LightGBM(4-seed) → top100（C 案已证明任何
输入层重组都在平台内移动）。分组的用途只剩一个：**监控与归因**——把"模型整体健康"
拆成"六块各自的健康"，让局部劣化可以被看见、被定位。

## 二、分组结构（与 C 案同一映射，保证实验与监控同语言）

## 三、落地项（按改动面排序，③ 需用户批准后动 `app/**`）

### ① 只读基线（今天已完成）
`experiments/factor_corr_36m.csv` = 分组结构的基线读数。未来任何时刻重算同口径矩阵，
**块内平均 ρ 结构突变（如 B1 三角解体、B2 聚类漂移）本身就是市场微观结构变化的第一信号**——
这是分组结构白拿的副产品，先于任何 IC 劣化报警。

### ② 台账登记（今天已完成）
05 号台账 C 案条目 + 本计划；判据：D 的输入层不动已由 C 案背书。

### ③ 监控接线（待批准，改动 `app/weekly` + `app/models`，预估 1~2h + 全量测试）
1. **块级 IC 追踪**（`health.py` 扩展）：生产打分逐锚点对每块因子组算块级秩 IC 滚动值；
   报警线 = 块级 IC 跌穿 0.5×该块历史均值（与 S4 修好的负 IC 分支同口径），
   P0 块报警 → 运维邮件；P1/P2 块只记录不上报。
2. **归因粒度**（`attrib.py` 扩展）：任一执行周期的超额分解到 6 个块的贡献
   （口径：块内因子持仓暴露加权），报数时并排"总超额 / 最大块贡献 / 最大块拖累"。
3. **B1 暴露守卫**（`protocol.py` 扩展）：size 暴露相对可交易域中位数的偏离 >1σ 时
   在周报标注（不动作，只标注——动作属于换 pin 级决策）。
4. **稀疏面板保护**（`factor_engine.neutralize` 调用侧守卫）：B6 类稀疏因子进入任何
   新计算路径前，先过非零占比检查（<2% 走 sparse 口径），把 F35 的教训做成默认门。
5. 守卫测试：块级 IC 用例（构造块劣化必须报警）、归因分解恒等式（块贡献和=总超额）、
   B1 偏离标注用例。

### ④ 验收（可量化）
- 监控覆盖率：P0 四块每块 ≥1 个读数进 doctor（14 项 → 18 项，契约测试同步）；
- 归因恒等式：|Σ块贡献 − 总超额| < 1e-6（每期）；
- 预警有效性回放：用 2021 年（模型分歧年）数据回放，块级报警须早于全模型 IC 报警 ≥4 周；
- 全量测试零回归 + 审计 10 项过。
