# B1 预注册 —— 回测基准腿换"全收益尺"的 A/B（2026-09-19 冻结，跑之前写死）

关联：三补二十五 §② B1（`scripts/oneoff/audit_bench_total_return_gap.py` 已量出抬高量）。
**本文写定时，两臂一次都还没跑，任何 Δ 读数都不存在。**

## 0. 这一轮要回答的问题

现行月频基线的 `excess_ann` 里，有多少只是**基准尺造成的抬高**（基准腿用价格指数、持仓腿用全收益），
换掉之后**两轴**（超额 / 最大回撤）各变多少，以及该不该换 pin。

## 1. 两臂定义（冻结）

| | 基准腿 | 其余一切 |
|---|---|---|
| **A（基线）** | 今天的样子：`m["bench"] = index_daily.close`（`000906.SH` 中证800 **价格指数**） | 完全不动 |
| **B（全收益尺）** | `bench_TR_t = bench_PR_t × Π_{s≤t}(1 + y_{m(s)}/1200/D_{m(s)})` | **与 A 逐字相同**：同一份 panel 对象、同一套参数、同一次进程内跑 |

`y_m` = 该月末**中证800 成分股市值加权 `dv_ttm`**（`index_weight` ∩ `daily_basic`，与 B1 审计同一个函数
`dividend_yield_by_month`，按文件路径 import 复用，不复制公式）；`D_m` = 该月交易日数；
`/1200` = 年化股息率(%) 摊到月度再摊到日（**平滑摊销**，不按真实除息日 lump 计入 —— 限制见 §5）。

## 2. 已知会变的与承诺不会变的（跑之前写死）

`engine.py` 里 `bench` 只出现在 `bret`(614) / `bench_nav`(665,670-672) /
`bench_ann`(700) / `excess_ann`(737) / `win_rate`(707) —— **没有一处进决策**（选股、状态映射、
迟滞、成交、止损都不读它）。据此本轮承诺：

**A0（复现检查，非判决门）** 基线臂 A 用生产同一入口
`run_backtest(start=cfg.eval_start)`（`eval_start: '20190722'` ⇒ 首个评分日 20190731、85 期），
读数应接近 08 号现行 pin（实读 `backtest_summary` 的 `20260912_limitquant` 行）：
> ⚠️ 时效注记（2026-09-27 追加）：现役 pin 已更迭为 **`20260927_excl5`**（第 6 次重钉：factor_exclusions 剔除 5 个 S5 判否因子，组合层档 PASS；05 号台账 十九/二十补）。下述 pin 数值均为**当时的 pin（历史值）**。

`ann 0.2262 / bench 0.0380 / excess 0.1882 / mdd −0.2410 / win 0.6706 / turnover 0.8912 / IC 0.0959`。
⚠️ **对不上不算失败**：KB 三补二十五与 F77 都已登记"生产 `model_score` 因 09-16~18 因子表刷新而过时"
⇒ A 与 09-12 那行之间本来就允许有数据漂移。A0 的作用是**量出这段漂移有多大**并如实写进产物，
**本轮判决不依赖它**（依赖的是下面 A1，它在同一进程同一 panel 上比较，完全不受数据漂移影响）。

**A1（前置不变性，红检 = 真正的门）** 除 `bench_ann`、`excess_ann`、`win_rate` 三个字段外，
两臂的**全部**指标必须逐位相等：`ann_return / max_drawdown / mdd_daily / sys_ann_return /
sys_max_drawdown / sys_mdd_daily / avg_turnover / ic_mean / ic_std / icir / 净值序列` 全部 Δ=0。
⇒ **只要有一条不等，本轮前提就被证伪**：说明 bench 实际上进了某条决策路径，
那就不是"报告尺"问题而是"决策污染"问题，等级升高，**立刻停手回去查**，不许顺手改判据。

**A2（量级门）** `Δexcess_ann = excess_ann(A) − excess_ann(B)` 必须落在 **[1.5, 3.0] pp/年**。
区间来源（跑之前已实测，非事后拟合）：B1 审计的年度股息率带 1.74~2.72pp/年，两侧各留 ~0.2pp 复利/摊销余量。
⇒ 落在带外 = 不采纳任何结论，先查口径实现（**这一条是用来抓我自己算错的**，不参与"要不要换"的判断）。

**A3（两轴判决）** 回撤轴 ΔMDD 必须 = 0（由 A1 保证）；超额轴报 Δexcess_ann 与 `win_rate` 的变化。

## 3. 判读（写于跑之前）

- **A1 全过 + A2 在带内** ⇒ 结论固定为一句话：*现行 `excess_ann` 被价格基准尺抬高 Δexcess_ann pp/年，
  决策与回撤完全不受影响*。此时**建议采纳 B 尺**（它才与持仓腿同尺），但
  **换 pin 由用户拍板**：换 = 重钉金标准（`bench_nav`/`excess_ann`/`win_rate` 三个字段会变）
  + 08 号台账 + config 注释 + README/02 号现行读数三方同步。
- **A1 有任一不过** ⇒ 前提证伪，本轮作废、登记新缺陷，不谈换 pin。
- **A2 落在带外** ⇒ 实现有错（最可能：摊销/月度映射/权重口径），修实现重跑，**不许把区间改到能过**
  （01 号：门禁只更严，不许顺手放宽）。
- 无论哪种结果，**不采纳时也要落地一件事**：在 README/02 号的相关超额读数旁就地标注
  "（价格基准尺，未计指数分红再投资）"，让读者自己知道尺在哪。

## 4. 分段与覆盖（写于跑之前）

`index_weight` 从 **20190131** 起有成分权重，而**现行 pin 的评估窗是 `20190722` 起（85 期）**

两组各两臂，共 4 次回测：`A/B`（生产窗，主）与 `A_full/B_full`（全史，敏感度）。

## 5. 已知限制（写于跑之前，不给事后留借口）

1. `bench_TR` 是**合成序列**，不是中证发布的真实全收益指数；`dv_ttm` 是过去 12 个月实发股息率，
   与指数编制用的口径有出入 ⇒ 抬高量是一阶估计。
2. 平滑日摊销 vs 真实除息日 lump 会计入的差别，**不影响年化读数**，但会影响 `win_rate`
   （逐月比较）与月内基准路径 ⇒ `win_rate` 的变化只作参考，不作判决。
3. 真实可投的替代做法（换用全收益指数代码 / 用 ETF 净值为基准）需要**新数据接入**，
   不在本轮范围；本轮只回答"差多少、要不要为此换 pin"。
4. 持仓腿的分红是 `adj_factor` 全额计入并按月复利（`engine.py:341`），
   **不模拟分红现金到账后再投资的费用与时滞** ⇒ 两臂都比真实可实现的收益略乐观；
   本轮不修这个，只是让**两条腿同尺**。

## 7. 跑中变更记录（第一版结果作废的如实登记）

同日 22:1x 第一次四臂跑完，A1/A2 都 PASS（Δexcess 生产窗 +2.36pp、全史 +2.34pp）。
**但那一版 B 臂的构造与 §1 冻结定义不符，读数作废**：`dividend_yield_by_month` 返回的索引是
`index_weight` 的**月末交易日**（`20190131`），而代码拿 `YYYYMM`（`201901`）去查表 ⇒
**92 个月一个都没命中**，整条序列静默退化成"常数窗口均值"。Δ 恰好仍落在 A2 带内
（均值≈逐月值的平均），**所以 A2 没有抓住它** —— 是复盘覆盖统计（"填充 3331 天" = 全面板）暴露的。

处置：
1. 修月键映射（`str(k)[:6]`），重跑 —— 见脚本 `tr_multiplier` 的注释；
2. 新增 **A3 / A4 两道实现完整性前置**（**不是**结果判据；A2 的区间一个字都没改）：
   - **A3** 判决窗（`eval_start` 起）内**缺失月数必须 = 0** —— §4 承诺"主证据不靠填充"；
   - **A4** B 臂必须真的用上**逐月** `y_m`（`max(y)−min(y) > 0`）—— 专门用来抓"退化成常数"这一类
     键形态/映射错配，因为它能让结果看着对而构造是错的。
3. 顺带把 A0 的容许差**算成判定**：`avg_turnover` 之比必须 = `n/(n−1)` = 85/84。
   原因跑之前就知道（05 号 P2-1：换手分母 2026-09-14 由 `n_periods` 改成"真正计入的期数"，
   当时 goldens 已故意重钉、只动这一个字段），含糊成"数据漂移"是不行的 ——
   实测 `0.8912 → 0.9018`，比值 1.0119 = 85/84 ✓ ⇒ **A 臂与 09-12 pin 行逐位相等**（除了那一个已知字段）。

教训（写下来给下一轮）：**"结果落在预期区间内"不能证明实现是对的** —— 这次 A2 通过、实现却是错的。
可复现的前提检查（覆盖统计、键形态、比例恒等式）比数值区间更能抓住这类错。
