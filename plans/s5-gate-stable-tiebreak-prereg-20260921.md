## 1. 问题（已核实到代码行）

`app/alpha/gate.py:96`：
```python
order = f.sort_values(ascending=False).index
```
`sort_values` 默认 `kind="quicksort"` —— **非稳定排序**。当分数并列时，"谁进 top-k"取决于输入顺序与算法，而非数值。

**实证**（`experiments/b_stage_20260920/m5_g3_channel_gate.json`）：
- 批次 4 实测 **4/7 条**零次齐次因子的头部边界并列间距 `boundary_gap_min_rms = 0`
- **71/71 个死区月末**的边界间距小于值噪声
⇒ 并列不是偶发，而是**结构性**的（尤其零次齐次因子）。

**后果**：同一份数据、不同输入顺序 ⇒ 选出的 top-k 不同 ⇒ 头部超额/多空价差读数不同。
机制根因与批次 4 G2 的 16 条翻动同源。

## 2. 冻结判据（实施时按此改）

### 判据 S5-1（确定性 tie-break）
```python
order = (f.rename("score").reset_index()
          .sort_values(by=["score", "ts_code"],
                       ascending=[False, True], kind="stable")["ts_code"].values)
```
即按 **(分数降序, 代码升序)** 排序，`kind="stable"` 保证稳定。

### 自证门
- **S5-a**：同一输入**无论行序如何打乱**，选出的 top-k 集合必须完全一致（用 `np.random.permutation` 打乱后重跑，断言集合相等）。
- **S5-b**：并列组内部必须按 `ts_code` 升序（可构造全并列输入验证）。
- **S5-c**：非并列情况下，排序结果与原实现**一致**（不得改变已有确定的相对顺序）。
