# B1-真尺 预注册 —— 基准腿换成中证800**全收益指数 H00906.CSI**（2026-09-19 冻结）

上游：三补二十七（合成尺 A/B 估出抬高 2.37pp/年）＋ 09 号"一之补"（探明 `H00906.CSI` 可达）。
本文写定时，`H00906.CSI` **一行都还没进库**，臂 C 没有任何读数。
**本轮不改 pin、不改生产口径**：它只负责把"换 pin 之后会怎样"用**真实指数**测出来，
换不换（重钉金标准 + 三方同步）由用户最后点。

## 0. 要回答的问题

把回测基准腿从价格指数 `000906.SH` 换成同一家中证公司发布的**全收益指数** `H00906.CSI`：
① 两条腿是不是真的对等尺了；② 超额读数变多少；③ 两轴里的**回撤轴**动不动；④ 决策动不动。

## 3. 门（跑之前写死）

**C1 数据对等性（前置，不过就别谈尺）**
1. `H00906.CSI` 的交易日集合与 `000906.SH` **完全相同**（双向差集 = 空），行数 = 3331；
2. 比值 `H_t / PR_t` **无实质下降段**：下降幅度 >0.001% 的天数必须 = 0
   （股息再投资只增不减；出现**实质**下降才说明取错列/错代码/日期错位）；
3. 端点法年化对照（写死预期，来源是 09 号实读）：生产窗 PR≈3.76% / H≈5.98%，
   全史 PR≈3.08% / H≈5.30% ⇒ 抬高中枢 **2.22pp/年**，两窗一致。

> **C1-② 的容差更正（首次跑之后，2026-09-19 深夜；详见 §7）**：本条原文只写了"单调不降
> （容忍 1e-6 浮点噪声）"，而脚本实现收得更紧（1e-9）⇒ 被 **744 处 1e-7 量级的抖动**判 FAIL。
> 那不是数据问题，是"文档写的容差没落到实现上"。更正后统一为 **0.001%**，并加上面 §4/§5 两道
> **正检查**：日期错位/接错列会让 §4 当场炸，而指数舍入不会 ⇒ 修完的 C1 比原式**更能**抓错，不是放水。
> C1-①、C1-③ 与 C2/C3 一字未动。

**C1-补 两道正检查（同一并冻结，专门用来抓"接错东西但比值看着还行"）**
4. 每条腿自己的 `close` 逐日收益必须与库里的 `pct_chg` 自洽（最大不符 ≤0.01%）——
   日期错位、接错列、混了另一只指数都会在这里当场炸；
5. 逐年 `(TR − PR) 收益和` 必须落在 **[0.5, 3.5] pp** 内 —— 这是"这条腿确实只多了股息"的直接检验
   （B1 独立估出的股息率带是 1.74~2.72pp/年）。

**C2 量级门**：`Δexcess_ann = excess(A) − excess(C)` ∈ **[1.8, 2.6] pp/年**（两窗各自都要落带内）。
带以 3-③ 的实测 2.22 为中心、两侧 ±0.4pp；引擎按月复利，与端点法会有几分 bp 差，故不给更窄的带。
**落在带外 ⇒ 判"接入或实现有错"，先查实现，不许改带。**

**C3 不变性门（本轮真正的判决）**：除 `bench_ann / excess_ann / win_rate` 外，
两臂全部指标（`ann_return / max_drawdown / mdd_daily / sys_* / avg_turnover / ic_* / 净值序列`）**逐位相等**。
⇒ 通过即证明：换尺**不动任何决策、不动回撤轴**，纯粹是"报出来的超额对不对"。
⇒ 不通过即前提证伪（基准进了决策），本轮作废并登记，**不许改门继续跑**。

## 4. 判读（写于跑之前）

## 5. 已知限制（写于跑之前）

1. `H00906.CSI` 覆盖 2004-12-31 起，本库只接 `START_DATE`(2013-01-04) 起 ⇒ 与其它指数一致；
   比 000906.SH 在库里的起点**不早于**它，故两窗全覆盖，无填充段（这是 09 号那条合成尺的头号限制，本轮消失）。
2. 持仓腿分红按 `adj_factor` **税前**计入 ⇒ 与 H(全收益) 同尺；若哪天改配 N(净收益，扣红利税)，
   那是"个人可实现收益"的另一道题，需另立口径，不许顺手换。
3. `adj_factor` 全额计入分红**不模拟**到账时滞与再投资费用 ⇒ 两臂都比真实可实现收益略乐观，本轮不修。
4. 真指数仍有编制层面的差异（全收益指数的再投资细则、样本调整），比合成尺的"平滑摊销"假设干净，
   但不是同一算法 ⇒ `win_rate`（逐月比较）变化只作参考。
