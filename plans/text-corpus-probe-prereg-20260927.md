# 预注册：文本语料源可行性探针（2026-09-27，采集前锁定）

> 方案 A（llm-factor-mining-survey-20260927.md §三.A）第一步。**探针只测源，不建管线、
> 不挖因子、不写生产表** —— 照 09 号数据族红线与 W2 CTA/CB 探针同款范式。

## 一、探针四问

1. **可及性**：当前依赖（tushare 1.4.29 + token / akshare）下，哪些文本源可调？
   逐源记录：接口存在性、报错/积分墙。
2. **覆盖度**：历史深度（min/max 日期、行/天）、个股粒度（per-stock vs 全市场 feed）、
   股票归属字段（ts_code/代码）。
3. **对齐性**：发布时间戳是否逐条可得（PIT 对齐月频锚点的前提）；公告类以发布日为准。
4. **体量**：全史回填的行数与存储估算；限频实测。

候选源（逐一尝试，失败即记因）：
- akshare `stock_news_em`（东财个股新闻，per-stock）
- akshare `stock_notice_report`（全市场公告，按日）
- tushare `news`（快讯 feed，sina 等源）/ `major_news`（大事）
- tushare 公告类接口名以 getattr 探测（`notice`/`anns` 等存在性不确定，如实记录）

## 二、判据（跑前锁定）

**探针 PASS** = 至少 1 个源同时满足：
(a) 文本可归属到个股（per-stock 或带代码字段）；
(b) 逐条时间戳；
(c) 历史深度 ≥ 12 个月（理想 ≥ 2019-01 以对齐 bank 面板窗）；
(d) 回填体量可行（全市场 ≤ ~5 万行/天量级，无硬积分墙）。

只有浅历史源可过 ⇒ 结论改为"**仅前向采集可行**（攒纸面样本，历史因子挖不动）"。
全部不可过 ⇒ 文本数据族在本仓当前依赖下关闭，登记后转方案 B（LLM 复盘角色）。

## 三、不做什么

不建日更管线、不写 `factor`/`alpha_bank`、不动生产 `model_score`/ens/config；
探针样本数据只进 `experiments/` JSON（截断内联，不落 parquet）。
判据 PASS 后的正式采集/因子构造**另立预注册**。

## 四、探针结果（2026-09-27 01:55，判据判定：**PASS**）

| 源 | 结果 | 记因 |
|---|---|---|
| akshare `stock_news_em`（东财个股新闻） | ✗ | akshare 1.18.94 内部正则 bug（`invalid escape sequence: \u`，Python 3.13 不兼容） |
| akshare `stock_notice_report`（全市场公告） | ✗ | KeyError `'代码'` —— 站点/接口改版，列名变更 |
| akshare `stock_telegraph_cls`（财联社电报） | ✗ | 1.18.94 无此属性（接口改名/移除） |
| tushare `news(sina)`（快讯 feed） | ✗ | **积分墙**：无 news 接口权限 |
| tushare `notice` 等公告接口 | ✗ | `notice` 不存在（`major_news`/`anns` 等属性存在但未展开测试） |
| **akshare `stock_zh_a_disclosure_report_cninfo`（巨潮个股公告）** | ✓ | **000001：2019-01-04 起 730 条**（97 条/年）；字段 = 代码/简称/公告标题/公告时间/公告链接；7.5 年单票 7.8s（分页串行） |

**判据对照（§二）**：(a) 个股归属 ✓（代码字段）；(b) 逐条时间戳 ✓（公告时间）；
(c) 深度 ≥ 2019 ✓（实测 2019-01-04 起）；(d) 体量可行 ✓（5800 股 × ~97 条/年 ≈
56 万条标题级/7.5 年，串行回填 ≈ 13h 一晚，存储 <1GB）。

**结论**：文本数据族探针 **PASS**，源 = **巨潮个股公告**（慢信息、公告效应文献主线）。
新闻快讯类 feed 在当前依赖/积分下不可及（如实记录，不影响 PASS 判定——公告是
"渐进定价"文献的主矿脉）。
**下一步（待拍板，另立预注册）**：正式回填管线（串行 + 断点续采 + manifest，照 09 号
数据族红线自设 cap）→ LLM 打标/嵌入 → 因子族 → 三层门禁。
